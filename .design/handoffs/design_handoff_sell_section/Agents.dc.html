The cut: Commissions stops being a screen
The rail draws the final map: Sell 6, Buy 2, Catalogue 4, Money 4, Insight 4, Setup 3 — 23 rows and Today, from 33 and Today. Every cut is argued in Rail.dc.html, which is the authority if a frame disagrees.
A commission screen reads the same order rows this one does and sums one field off them — bonusCommission, filtered to completed, not voided, bucketed by the order's own month. The agent app already shows the agent that figure. An admin screen that recomputes it is a second implementation of one rule, and the reconciliation test exists precisely because the two have drifted before: a bonus shown as earned that the payout would not pay.
What is lost
A month-by-month commission table. It returns as three figures on the agent panel — shown as earned, claimable, not yet counted — which is the only comparison anyone opens that table to make.
What absorbs it
This screen's agent panel, plus one Pay the bonus action on the month. The payout stays where the record is, so a claim is made against the figure being looked at.
The words still reach it
"commission", "bonus", "earnings" and "payout" become Agents keywords, and resolveTab('commissions') opens Agents with the bonus block scrolled to.
Three things this screen now says that the data always held: one row holds three profits — yours, theirs, and the supplier's bonus, and the waterfall shows all three against your cost. What an agent owes is the shop price on delivered orders, never their client price, which is why the owed figure is 1.42m and not 1.78m. And agent margin runs half the counter's, because agent rounds are mostly cement — so the lever is what they carry, not what you charge. Next screen: WhatsApp.
